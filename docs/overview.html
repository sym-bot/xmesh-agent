what is it

Autonomous peers, plainly

A peer is one process that wakes on an incoming message, calls a model, and emits a response — agent-to-agent, no central server. Every other peer decides for itself whether that response is relevant.

No router, no orchestrator. Admission is the receiving agent's own call. The autonomous agent runtime for xmesh.dev, built on @sym-bot/sym.

two functions

One runtime, two jobs

  • Real-time duplex comms — peers exchange messages directly via Bonjour (LAN) or a WebSocket relay. No polling, no coordinator.
  • Autonomous collective intelligence — each peer wakes, reasons with its model, emits. The receiver admits per-field via its own α-weights. Aligned peers converge; divergent peers stay sovereign.

guardrails

Safety envelope

  • Wake-budget — burst / sustained / daily caps, soft-warn at 80%
  • Cycle detection — suppress emission when lineage loops back
  • Token + cost cap — per-call + per-run, auto-stop on overrun
  • Approval gates — block git push, deploy, .env, secrets
  • Circuit breaker — opens after 5 failures, exponential backoff
why not a framework

vs CrewAI / AutoGen / LangGraph

  • Who answers? the receiving agent decides per message — not routing you configure
  • Unknown agents contribute? yes — any coupled peer
  • Irrelevant agents waste tokens? never — the gate rejects silently
  • Headless, no host IDE? native — background peers
  • Traceable? always — lineage DAG
use it

Define a peer & run

npm install -g @sym-bot/xmesh-agent

# validate config + adapter, no mesh join:
xmesh-agent dry-run --config reviewer.toml

# run headless, then seed a task from another shell:
xmesh-agent run --config reviewer.toml
sym observe --group my-team --focus "…" --intent "…"

A peer is one agent.toml: identity, group, role α-weights, model. Add a writer + test-writer to the group and they coordinate.
